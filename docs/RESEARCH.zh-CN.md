研究采集始于 2026-10-13（北京时间），实现跨至 2026-10-14。下表 Star 数来自当时的 GitHub 公共 REST API；原始字段保存在 [research-snapshot.json](research-snapshot.json)。数字会变化，不是增长预测。

这些是有目的选取的成功案例，不是随机样本。没有低星对照组、访客转化数据或历史增长控制。因此以下是**产品设计推断**，不能据此断言某个特征导致高 Star。

## 能借鉴的共同倾向

### 1. 首先解决一个能够说清的需求

“传文件”“管理照片”“画图”“把仓库给 AI”都是用户已经理解的动作。用户不用先接受一套新理念。RepoPrism 的对应需求是：**在陌生仓库里找到相关代码，并把它交给 AI。**

上一版夜航的计时和便笺也有需求，但可替代产品很多，没有提供足够鲜明的选择理由。漂亮界面单独不足以成立。

### 2. 第一次操作应该产生可见的结果

Excalidraw 的图、Mermaid 的图表、截图转代码的对比，都能说明“这个项目到底做了什么”。RepoPrism 首屏直接加载标注清楚的交互示例，不要求注册或准备 API Key；导入后显示的是用户自己的代码结构。

### 3. 成果应当能进入下一步工作

有价值的导出比分享按钮更重要。RepoPrism 的地图可放进项目文档；报告可用于审查；选择后的上下文可进入用户自己的 AI 工具。传播来自有用的产物，而不是虚构的使用人数。

### 4. 可信任会影响是否敢于尝试

LocalSend 的本地传输、Excalidraw 的本地优先，以及 Repomix 的敏感信息检查，为工具进入实际工作提供了理由。RepoPrism 采用浏览器本地导入、Web Worker 分析、无遥测、内存保存和已知模式遮盖。这里没有承诺完美检出秘密或安全审计能力。

### 5. 有可重复的用途和参与入口

一次惊艳容易收藏，重复解决问题才容易留下用户。RepoPrism 的重复场景包括接手项目、定位修改范围、审查一个模块、准备 AI 上下文。贡献入口聚焦可复现的导入与过滤失败，不依赖“欢迎所有贡献”的空泛口号。

## 为什么选这个方向

以下评分是选题判断，不是市场数据。每项 1–5 分，等权，总分只用于本次选择。

| 候选                       | 明确需求 | 演示效果 | 使用门槛 | 重复用途 | 当前可做出可信版本 | 总分 |
| -------------------------- | -------: | -------: | -------: | -------: | -----------------: | ---: |
| 计时与便笺                 |        3 |        2 |        5 |        3 |                  5 |   18 |
| 通用 AI 聊天外壳           |        3 |        3 |        2 |        4 |                  3 |   15 |
| 仓库可视化与上下文选择     |        4 |        4 |        5 |        4 |                  4 |   21 |
| 全自动修改任意项目的 Agent |        4 |        5 |        2 |        4 |                  1 |   16 |

选择仓库工具的理由是：用户群接近 GitHub 主要受众，输入输出清楚，可以在不依赖模型、账号或付费 API 的情况下交付真实功能。它的风险也明确：现有工具已经很成熟，不能把“代码转提示词”当成新发明。

## 与相邻工具如何区分

| 项目        | 仓库说明中的核心方向          | RepoPrism 的关系                                       |
| ----------- | ----------------------------- | ------------------------------------------------------ |
| Repomix     | 仓库打包、AI 上下文与丰富配置 | 不竞争完整打包能力，侧重导出前的可视化理解与手动选择。 |
| Gitingest   | 便捷获取仓库的提示词友好文本  | 使用本地文件导入与交互工作台，当前没有远程 URL 获取。  |
| code2prompt | CLI、模板与 token 计数        | CLI 作为补充入口，主要体验在可视地图和文件详情。       |

本次没有声称 RepoPrism 的组合在市场上独一无二，也没有证明用户会从这些项目迁移过来。是否值得继续投入，需要实际使用反馈。

## 本次落实到了哪些东西

- 浏览器本地导入文件夹和 ZIP，分析在线程中运行。
- 按文件体积布局的目录地图，支持筛选、进入目录和 SVG 导出。
- JS / TS / Python 的静态导入启发式，依赖与调用方详情、两层依赖加入。
- 循环依赖、大文件、共享模块、TODO 与已知秘密模式线索。
- 确定性的任务匹配推荐，包含包装开销的估算预算、超预算提示、遮盖后的 Markdown。
- 同引擎 CLI、生产构建、离线应用壳、可双击使用的独立 HTML、双语 README、真实截图与浏览器测试。

## 不能用 Star 代替的验证

发布前的 0.2.0 修订已增加 JS / TS 语法解析、常见 TypeScript 路径别名、未解析关系提示、预算排除候选说明、完整上下文预览和导入取消。具体变化见 [CHANGELOG.md](../CHANGELOG.md)。这些修订针对初版实测发现的可靠性与操作问题，尚不构成用户需求已经验证的证据。

发布之后首先观察：别人能否成功导入自己的仓库；地图是否帮助他们找到原先没看懂的关系；推荐文件是否需要大量修改；是否愿意在第二个项目继续使用。当前尚未收集这些真实用户数据。

建议记录有明确问题的反馈，而不是先收集账号和遥测。邀请使用者附上可公开的最小复现，修复高频阻塞，再决定加入别名解析、分词器或 AST。具体发布材料在 [LAUNCH-KIT.zh-CN.md](LAUNCH-KIT.zh-CN.md)。

本次交付的是一个有选题依据、可运行、可验证的开源起点。高 Star 仍取决于需求是否成立、维护质量、传播和时间。
